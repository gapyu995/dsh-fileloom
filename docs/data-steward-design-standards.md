# Fileloom（织序）设计规范

版本：v0.2
适用范围：`packages/client/ui-file-manager` 的所有页面与组件。

## 1. 基本原则

1. **一屏一件事**：一个页面只有一个主任务和一个主按钮。
2. **先内容后系统**：最近文件、待办、整理方案优先；索引、ID、哈希靠后。
3. **无不可撤销的误操作**：删除进回收站；整理先备份；撤销前检查冲突。
4. **状态必须可见**：加载、空、错误、禁用、忙碌、成功都有明确表现。
5. **应用内交互**：不使用 `window.alert/confirm/prompt`。
6. **语义 token**：颜色/背景/边框一律使用 DSH 语义 token，不在组件里写死颜色（品牌色例外已由 token 覆盖）。
7. **文案可操作**：按钮用动词；错误说下一步；空状态给行动。

## 2. 设计 token

### 2.1 间距（4px 基准）

| Token | 值 | 用途 |
|---|---|---|
| `--st-space-1` | 4px | 图标与文字、徽标内 |
| `--st-space-2` | 8px | 同行控件、按钮组 |
| `--st-space-3` | 12px | 卡片内部小分组 |
| `--st-space-4` | 16px | 卡片内边距、行间 |
| `--st-space-5` | 20px | 页面内边距 |
| `--st-space-6` | 24px | 区块间距 |
| `--st-space-8` | 32px | 页面上下留白 |

禁止使用 5/7/9/13 等无规律间距。

### 2.2 字号

| Token | 值 | 用途 |
|---|---|---|
| `--st-text-xs` | 12px | 辅助信息、路径、徽标 |
| `--st-text-sm` | 13px | 正文、表格、按钮 |
| `--st-text-md` | 14px | 页面基础字号 |
| `--st-text-lg` | 16px | 区块标题 |
| `--st-text-xl` | 24px | 页面标题 |

正文不小于 13px；辅助信息不小于 12px；不使用 11px 以下正文。路径和 ID 用等宽字体，同时保证对比度。

### 2.3 圆角与阴影

- `--st-radius-sm` 6px：菜单项、小控件。
- `--st-radius-md` 8px：按钮、输入框。
- `--st-radius-lg` 8px：独立内容项、表格容器。
- `--st-radius-xl` 12px：弹窗。
- 页面区块不使用外层卡片、渐变和阴影，以留白和分隔线区分；浮层/弹窗使用 `--st-shadow-pop`。

### 2.4 颜色

只使用 DSH 语义 token：

- 背景：`--dsw-alias-bg-base`、`bg-layer-1`、`bg-layer-2`、`bg-overlay`
- 文字：`label-primary`、`label-secondary`、`label-tertiary`
- 边框：`border-l1`、`border-l2`
- 品牌：`brand-primary`
- 状态：`state-error-primary`、`state-success-primary`、`state-warn-primary`、`state-warn-label`、`state-business-primary`

品牌浅底用 `color-mix(in srgb, var(--dsw-alias-brand-primary) 10%, transparent)`，不写死 RGBA。

主按钮必须使用 `--dsw-alias-button-primary-fill` + `--dsw-alias-label-primary-foreground`，不要用品牌色 + 白色文字：深色主题下品牌色变亮，白字会失去对比度。状态徽标文字使用 `--st-*-text`（状态色与 `label-primary` 混合），避免亮绿/亮黄在浅色背景上对比不足。

## 3. 布局

### 3.1 全局

- 头部最小高度 72px，包含品牌、主导航、根切换、AI 入口。
- 页面内容最大宽度：首页 1400px，其他页 1240px，居中。
- 首页由工作台标题、扫描概览、文件主区和操作辅助栏组成；最近文件使用行列表，上传、待办和最近整理位于辅助栏。未建立清单时，文件数和容量显示 `--`，不伪装成零。
- 内容区独立滚动，面板本身不滚动。
- 响应式断点：
  - ≤1100px：文件详情栏 320px。
  - ≤980px：隐藏文件详情栏，首页辅助栏移至文件区下方。
  - ≤760px：导航换行、文件夹侧栏隐藏，首页上传模块优先显示，整理步骤纵向排列、弹窗全宽。

### 3.2 文件页

- 三栏：220px 文件夹 / 自适应列表 / 360px 详情。
- 列表是唯一滚动容器；详情栏独立滚动。
- 搜索框最大 380px，移动端占满一行。

### 3.3 表单页

- 单列，最大宽度 1200px。
- 整理三步纵向排列，每步 24px 上下内边距，以细线分隔，不包裹外层卡片。
- 规则编辑为 1fr + 250px 说明栏，窄屏堆叠。

## 4. 组件规范

### 4.1 Button

- 高度：md 34px，sm 30px。
- 变体：
  - `primary`：每个区域最多一个，用于推进主流程。
  - `secondary`：普通操作。
  - `ghost`：次要/取消/链接式操作。
  - `danger`：破坏性操作（删除、重置）。
  - `subtle`：品牌浅底（预留）。
- 忙碌：显示 Spinner 并禁用；不要只改文字。
- 禁用必须能从上下文推断原因；否则在附近给出解释。

### 4.2 IconButton

- 28×28，必须有 `aria-label` 和 `title`。
- 图标本身不传达唯一信息；重要操作配文字。

### 4.3 Badge

- 高度 20px，胶囊；同时有颜色和文字。字号不小于 11.5px。
- 语义：success（可搜索/已完成）、warning（待更新/重名）、danger（失败）、info（进行中/自动备份）、brand（当前/收件箱）、neutral（普通标签）。

### 4.4 输入

- 高度 36px；自动聚焦首个输入。
- 标签在上方（13px 次要色）；错误在下方（13px 红色）。
- 占位符不作为标签替代。
- 回车提交当前表单。

### 4.5 Dialog

- 宽度 440–820px，视内容；移动端最大 92vh。
- 必须支持：Esc、遮罩点击、焦点限制、关闭后恢复焦点。
- 头部：标题 + 可选说明；右上角关闭。
- 底部：取消在左、主操作在右；危险操作用 danger。
- 执行中禁止关闭；主按钮 busy。

### 4.6 表格

- 表头 sticky；12px；次要色。
- 行高由 10px 上下内边距决定；数字使用 tabular-nums；悬停浅底；选中品牌浅底。
- 路径列截断但保留 `title`；操作列右对齐。
- 空表不渲染表头，改为 EmptyState。
- 大量数据容器自身滚动，不让页面横向滚动。

### 4.7 EmptyState

- 图标 + 标题 + 一句解释 + 一个行动。
- 不写“暂无数据”；说明为什么空、下一步是什么。
- 紧凑版用于卡片内部，常规版用于整页。

### 4.8 Toast

- 固定底部居中，5 秒自动消失，可手动关闭。
- 成功/错误/信息三种左侧色条；错误不能只靠 toast（页面内也要有错误条）。
- 不承载需要用户决策的信息。

### 4.9 菜单

- 行操作统一进“更多”菜单；菜单项含图标和文字。
- 最多 6 项；破坏性项置底、红色。
- 点击外部/Esc 关闭；焦点回到触发按钮。

### 4.10 导航

- 主导航最多 3 个目的地 + 1 个“更多”。
- 当前项：深色文字 + 品牌色底部细线 + `aria-current="page"`。
- 次级目的地放在“更多”菜单，当前次级页时“更多”保持高亮。

## 5. 状态规范

| 状态 | 表现 | 禁止 |
|---|---|---|
| 加载 | 局部 Spinner + 文案 | 全屏白屏、按钮无反馈 |
| 空 | EmptyState + 行动 | 只显示“暂无数据” |
| 错误 | 错误条 + 重试；保留上下文 | 吞错、只弹 toast |
| 忙碌 | 按钮 Spinner + 禁用 | 允许重复提交 |
| 成功 | toast + 结果卡片/列表刷新 | 只 toast 不刷新数据 |
| 禁用 | 按钮禁用 + 原因 | 静默禁用 |
| 过期 | 明确“已过期/清单已变化” + 重新生成 | 自动重新执行 |

## 6. 破坏性操作规范

1. 全部使用应用内 ConfirmDialog。
2. 标题是问题，不是动作；正文说明影响范围、是否可撤销。
3. 确认按钮用动词，不用“确定”。
4. 执行中禁止关闭。
5. 失败必须说明是否已回滚。
6. 撤销前必须检查冲突；不允许“尽力恢复”后在 UI 里隐藏部分失败。
7. 永久删除在 v0.2 不提供；不要用“删除”暗示不可恢复。

文案示例：

- 删除：“「file.zip」会被移到回收站，之后可以恢复。”
- 整理：“执行后会改变文件位置。你可以随时在整理记录中撤销。”
- 撤销：“系统会先检查所有文件是否仍在原处，再把 12 个文件恢复。被修改过的文件不会被覆盖。”

## 7. 文案规范

- 动词开头：更新文件清单 / 生成整理方案 / 开始整理 / 撤销这次整理。
- 使用用户词：文件、文件夹、收件箱、最近文件、整理记录、备份点；不用 index、plan、rollback、snapshot 作为主文案。
- 数字带单位：“12 个文件”“1.2 GB”。
- 错误回答三问：发生了什么？文件安全吗？下一步做什么？
- 避免“智能”“自动帮你”“一键无忧”等夸大表述。
- 中英文都必须可切换；新增文案必须同时补 `zh` 和 `en`。

## 8. 可访问性

- 所有交互元素可键盘到达；focus-visible 清晰。
- 弹窗焦点限制、Esc 关闭、关闭后恢复焦点。
- 图标按钮有 `aria-label`；导航有 `aria-current`。
- Toast 使用 `aria-live="polite"`；错误条 `role="alert"`。
- 不单靠颜色区分状态；状态有文字。
- 正文 ≥13px，辅助信息 ≥12px；状态文字使用本地混合色保证明暗主题对比度。
- 拖放区域同时提供点击选择，键盘可触发。
- 表格行可点击时，双击/回车的行为必须一致（目录进入、文件预览）。

## 9. 代码规范

- 一个页面一个文件；共享组件放 `components/`；页面不直接写全局颜色/间距。
- CSS Modules；类名语义化；动态类名集中在组件内。
- 所有 API 调用通过 `FileManagerApi`；组件不直接拼 URL（预览 URL 除外）。
- 错误沿用服务端 message；不把 HTTP 状态码当用户文案。
- 组件 props 显式类型；避免 `any`。
- 用户可见文案全部来自 `locales.ts`；不散落硬编码中文。
- 选项对象遵循 `exactOptionalPropertyTypes`：可选字段用条件展开，不传 `undefined`。
- 文本输入、按钮、弹窗必须考虑禁用/忙碌状态。
- 新增 API 路由必须检查 path 唯一（dsh 精确路由按 path 单键）。

## 10. 评审清单

- [ ] 首屏是否直接回答“最近有什么/我需要做什么”？
- [ ] 主按钮是否唯一且动词明确？
- [ ] 破坏性操作是否有影响说明和撤销路径？
- [ ] 加载/空/错误/忙/成功是否都覆盖？
- [ ] 是否使用应用内弹窗而非原生 prompt/confirm？
- [ ] 弹窗是否支持 Esc、焦点限制、焦点恢复？
- [ ] 是否使用了语义 token，而非硬编码颜色？
- [ ] 字号是否 ≥13px（辅助信息 ≥12px）？
- [ ] 移动端 ≤760px 是否可用（无横向滚动）？
- [ ] 新增文案是否中英齐全？
- [ ] 技术 ID 是否只出现在详情/复制场景？
- [ ] 失败后文件是否保持安全、可解释、可重试？
