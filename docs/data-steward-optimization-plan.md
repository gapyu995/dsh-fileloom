# 数据管家界面与产品优化计划

版本：v0.2
状态：P0 已实现；P1/P2 待排期。
配套：[设计文档](data-steward-design.md)、[设计规范](data-steward-design-standards.md)、[架构](data-steward-architecture.md)。

## 1. 背景

旧版界面是“API 的可视化外壳”：六个平铺 Tab、按钮直接映射后端动作、原生 prompt/confirm、技术 ID 作为主信息。它能跑通流程，但不是产品。用户提出的问题非常具体：

1. 随手拖入一个文件，不看文件夹，下次怎么保证一眼看到？
2. 有没有“最近文件”和“打开时的推荐文件”？
3. 操作逻辑不够清晰，界面应该更简化、更易懂。
4. 需要可维护的架构文档、设计文档和设计标准。

本计划先回答这些问题，再给出分阶段落地路径。

## 2. 现状审计（旧版）

### 2.1 信息架构问题

| 问题 | 证据 | 后果 |
|---|---|---|
| 六个 Tab 平铺：文件/概览/规则/快照/回收站/设置 | `FileManagerPage.tsx` 旧版 `Tab` 联合类型 | 地点、任务、历史、配置混在一起 |
| “扫描”“生成整理计划”“快照”“回滚”概念并列 | 旧版头部四个按钮 | 用户不知道先后关系 |
| 概览与文件都能扫描 | 旧版 `doScan` 跳转到 overview | 同一动作出现在两个上下文 |
| “快照”承担操作历史职责 | 旧版 snapshots 表直接提供回滚 | 用户找不到“上次整理记录” |

### 2.2 操作逻辑问题

| 问题 | 证据 | 后果 |
|---|---|---|
| 生成计划依赖上一次扫描，但界面不提示 | 旧版 `doClassify` 直接调用 | 报错“run scan first” |
| 计划只展示 10 条样例 | 旧版 `plan.samples.slice(0, 10)` | 用户无法检查完整移动清单 |
| 执行后只有 toast 带 ID | 旧版 `organizeDone` | 没有“撤销”入口 |
| 没有操作记录列表 | 旧版只有 snapshots | 无法按操作撤销 |
| 手动快照回滚语义与操作回滚混在一起 | 旧版 `doRollback(snapshot)` | 用户不知道恢复什么 |
| 新建/重命名/移动/复制全用 `window.prompt` | 旧版四个函数 | 无法浏览目标目录，路径手输易错 |
| 目录不能删除，但界面无解释 | 旧版仅对 file 显示操作 | 用户以为功能坏了 |
| 搜索无索引时直接报后端错误 | 旧版 `doSearch` | 没有“先更新清单”的引导 |
| 回滚冲突直接显示原始 409 文本 | 旧版 `run` 捕获后塞进错误条 | 用户不知道哪些文件冲突 |

### 2.3 产品能力缺口

| 缺口 | 影响 |
|---|---|
| 没有上传 | 用户无法把文件放进来，只能浏览已有目录 |
| 没有“最近文件” | 随手放进来的文件下次找不到 |
| 没有“打开时推荐” | 首页没有回来的理由 |
| 没有收件箱 | 不知道新文件默认落在哪里 |
| 没有持久化的进入记录 | 关闭页面后“最近”丢失 |
| 上传不更新索引 | 新文件搜索不到，必须重新扫描 |
| 整理后索引不更新 | 搜索路径过期，下次整理预检失败 |

### 2.4 界面与可访问性问题

- 基准字号 11–12px，路径和操作按钮过小。
- 每行四个文字按钮，视觉噪音大。
- 原生 prompt/confirm 打断体验，无法统一样式与键盘行为。
- 弹窗没有焦点限制、Esc 关闭和焦点恢复。
- 错误、忙碌、空状态混用：busy 显示在 toast 里，会覆盖成功提示。
- 右侧详情在 900px 以下直接消失，没有替代入口。
- 文案中英混杂（名称、状态枚举、ID 前缀）。

## 3. 产品答案

### 3.1 “随手拖入、不看文件夹，下次怎么一眼看到？”

v0.2 的答案由四层保证：

1. **默认落点明确**：首页拖放/选择始终进入 `收件箱/`；文件页拖放进入当前文件夹。
2. **持久收件记录**：每次上传写 `ingest.json`，客户端关闭、服务重启都不丢。
3. **首页第一屏**：默认打开首页，“最近文件”展示最近 8 个，可展开全部；点击直接定位文件。
4. **搜索立即可见**：上传同时增量更新索引，不需要再扫描；首页卡片标注“可搜索/待更新”。

推荐区还会显示“收件箱有 N 个文件待整理”，引导用户下一步，而不是让文件永远堆着。

### 3.2 “有没有最近文件和打开时的推荐？”

有。最近文件来自服务端收件记录；最近打开来自浏览器本地记录；推荐是四条可解释规则：

- 收件箱待整理 → 去整理
- 没有文件清单 → 去更新
- 上次浏览路径 → 继续浏览
- 上次整理成功 → 可撤销

推荐不使用模型分析文件内容，避免隐私和不可解释问题。

### 3.3 “界面简化、逻辑清晰”

- 导航从 6 个平铺 Tab 收敛为：首页 / 文件 / 整理 / 更多（记录、回收站、规则、设置）。
- 首页承担“回来先看什么”；文件页只负责浏览与单文件操作；整理页只负责批量流程。
- 整理固定为三步：更新清单 → 预览方案 → 确认整理；每步只有一个主按钮，失败/过期/无索引都有明确状态。
- 执行结果立即提供“撤销”和“查看记录”，不再只给 ID。
- 所有弹窗改为应用内组件，支持 Esc、焦点限制与恢复。

## 5. 优化计划（P1/P2）

### P1：把“产品或可用”变成“产品好用”

| 优先级 | 事项 | 价值 | 验收 |
|---|---|---|---|
| P1 | 文件批量选择与批量移动/删除 | 整理单文件太慢 | 多选、批量确认、部分失败报告 |
| P1 | 上传进度与失败重试 | 大文件/多文件体验 | 单文件进度、失败项可重试 |
| P1 | 最近文件的“已读/未读” | 下次打开知道哪些是新的 | localStorage 水位；无存储时降级 |
| P1 | 文件夹删除（进回收站） | 功能一致性 | 递归删除、快照、恢复冲突检查 |
| P1 | 快照/操作详情分页 | 大于 500 文件仍可用 | 服务端分页、虚拟滚动 |
| P1 | 后台 watcher + 增量索引 | 新文件自动出现 | 手动刷新以外的更新路径；可关闭 |
| P1 | 键盘导航与行内操作 | 高频用户效率 | 方向键、Enter、Delete、重命名快捷键 |

### P2：从本地工具到长期数据管家

| 优先级 | 事项 | 价值 |
|---|---|---|
| P2 | dsh approval 接入 | 真正的人类确认，而不是 `confirm: true` |
| P2 | 可视化规则编辑器 | 非技术用户可维护规则 |
| P2 | 元数据补全（EXIF/TMDB/MusicBrainz） | 更聪明的分类 |
| P2 | 重复文件检测与清理 | 真实存储收益 |
| P2 | 原生快照适配器（Btrfs/ZFS） | 大目录下更快更可靠 |
| P2 | 多根权限与只读根 | 更安全的目录授权 |
| P2 | URL 深链接 / 面板内路由 | 可分享到具体目录/记录 |
| P2 | 上传后自动规则（默认关闭） | 高级用户自动化 |

## 6. 验收标准

### 6.1 本轮 P0

- [x] 首页默认打开，显示最近文件、推荐、最近整理。
- [x] 拖入文件进入收件箱；关闭页面再打开，最近文件仍在。
- [x] 上传后搜索立即可见（无需重新扫描）。
- [x] 整理流程三步均可完成；方案可筛选、分页；执行后显示撤销入口。
- [x] 整理成功后撤销可恢复；目标被修改时拒绝撤销并说明原因。
- [x] 删除进入回收站，可恢复；原路径占用时冲突可见。
- [x] 规则可读、可编辑、可校验、可恢复默认。
- [x] 所有确认/输入使用应用内弹窗，Esc 可关闭。
- [x] 页面无横向滚动；≤760px 可完成主要流程。
- [x] 中英文案齐全；技术 ID 不占主位。

### 6.2 度量（后续收集）

- 首次上传到首页可见的步骤数：≤ 1 次拖放 + 0 次跳转。
- 整理任务完成率：看到方案后点击执行的比例。
- 撤销率与撤销失败率。
- 搜索无结果后的下一步点击率。
- 页面错误率（4xx/5xx）与重试成功率。

## 7. 决策与取舍

| 决策 | 理由 |
|---|---|
| 首页而不是文件页作为默认 | 回答“回来先看什么”，而不是“系统有哪些目录” |
| 最近文件来自服务端记录，不用 mtime | 文件 mtime 会被外部工具改变，无法代表“我放进来” |
| 推荐用规则，不用模型 | 可解释、隐私友好、无额外延迟 |
| 上传默认不自动整理 | 自动移动会让用户找不到文件 |
| 删除不提供永久删除 | 本地数据不可逆风险高 |
| 规则先 JSON 后表单 | 规则表达力强，表单成本高；先保证可见可校验 |
| 导航 3+更多 | 保留低频功能，同时避免首屏认知过载 |
